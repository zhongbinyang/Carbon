# JTT1031 寄存器读写独立工具设计

日期：2026-07-22
状态：已获用户确认

## 背景与目标

依据《阶梯科技测试系统--底层通信协议JTT1031》，先实现光模块**按寄存器模式**的读写命令：

- `0x0016` 读光模块（寄存器模式）
- `0x0017` 写光模块（寄存器模式）

交付一个**独立 GUI 测试工具**：自管串口、自组帧/解帧，用于现场联调。

## 范围

**本期做**：

- 单文件独立工具（协议收发 + tkinter GUI）
- 仅支持命令字 `0x0016` / `0x0017`
- 串口参数默认：`115200`、8N1、无校验
- 连接面板、参数输入、读/写操作、HEX/ASCII 结果、收发日志

**本期不做**：

- 不复用 `jtt1031_iic.py` / `BasePage` / Carbon ToolBox
- 不做 Page 模式（`0x0012` / `0x0013`）及其他命令字
- 不做 UDP、固件升级、打包 exe（后续按需）

## 已确认的决策

| 决策点 | 结论 |
|---|---|
| 命令范围 | 仅 `0x0016` / `0x0017` |
| 形态 | 独立 GUI 窗口（方案 B） |
| 代码复用 | **不共用**现有模块；本工具内自实现串口通信与帧协议 |
| UI | tkinter，与项目其他工具风格接近即可 |
| 入口 | `python src/jtt1031_reg_tool.py` |

## 通信协议（本工具内实现）

物理层：异步串口 RS232。PC 发起，下位机应答。

帧格式（多字节大端；checksum = 前面所有字节之和的低 8 位）：

```
0xA5 (下发) / 0x5A (上报)
| address (1B)
| length  (2B, 含整帧所有字节)
| command (2B)
| data...
| checksum (1B)
```

### `0x0016` 读

下发 data：`port, dev-address, start-reg, size`（size 1..128）

回复 data：`state, port, dev-address, start-reg, size, read-data[size]`  
`state==1` 有效，否则报错。

### `0x0017` 写

下发 data：`port, dev-address, start-reg, size, write-data[size]`（size 1..128）

回复 data：`state, port, dev-address, start-reg, size`  
校验 state 与回显参数一致。

## 界面

1. **连接区**：COM 扫描/刷新、波特率（默认 115200）、业务板地址（默认 0）、连接/断开
2. **参数区**：光模块端口 `port`、器件地址 `dev`（默认 A0）、起始寄存器 `start`、读长度 `size`、写数据 Hex（空格分隔）
3. **操作区**：读 / 写按钮；结果显示 HEX + ASCII；写成功提示
4. **日志区**：TX/RX 整帧 hex

读写在后台线程执行，避免卡住 UI；未连接时禁用操作按钮。

## 错误处理

- 超时：读响应头/体失败时给出明确提示（检查串口、地址、板卡是否在线）
- 校验失败：帧头非 `0x5A`、地址不符、checksum 错、命令字不符、`state!=1`、回显参数不一致
- 参数校验：数值解析失败、size 超范围、写数据为空或超 128 字节

## 测试

- 单测覆盖：组帧、解析、checksum、`0x0016`/`0x0017` 请求与成功响应路径（FakeSerial）
- 联调：真实串口由人工验证（不作为 CI 依赖）

## 成功标准

- 单独启动窗口，连上业务板后可完成一次寄存器读、一次寄存器写
- 日志可见完整收发帧
- 不依赖 Carbon ToolBox 或其他协议模块即可运行（仅依赖 `pyserial` + 标准库 tkinter）
